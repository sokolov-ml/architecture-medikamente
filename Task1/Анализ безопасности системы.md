# Анализ безопасности системы "Медикаменте"

## 1. Выявление конфиденциальных данных и процессов

### Конфиденциальные данные:

| Категория данных   | Примеры                       | Текущее хранение | Риски                              |
| ------------------ | ----------------------------- | ---------------- | ---------------------------------- |
| PII (Персональные) | ФИО, паспорт, СНИЛС, адрес    | Excel, сканы     | Утечка, несанкционированный доступ |
| PHI (Медицинские)  | Диагнозы, анализы, назначения | PDF/JPG, Excel   | Нарушение врачебной тайны          |
| Финансовые         | Платежи, реквизиты договоров  | 1С, Excel        | Мошенничество                      |
| HR-данные          | Зарплаты, кадровые документы  | 1С, файлы        | Утечка персональных данных         |

### Критические бизнес-процессы для DFD:

1. Запись пациента на приём
2. Обработка медицинских данных
3. Финансовые операции
4. Учёт ТМЦ
5. Интеграция с лабораторией

## 2. Аудит мер безопасности

### Проблемные зоны:

1. **Хранение данных**:

   - Отсутствие шифрования (Excel/PDF)
   - Нет разграничения доступа к файлам
   - Нет журналирования доступа

2. **Обработка данных**:

   - Ручной ввод → риск ошибок
   - Нет валидации входных данных
   - Данные дублируются в разных системах

3. **Передача данных**:

   - Нет защиты при передаче (например, в лабораторию)
   - Использование OLE в 1С → уязвимости

4. **Соответствие требованиям**:
   - Не соблюдается 152-ФЗ (персональные данные)
   - Нет DLP-системы
   - Нет назначенного ответственного за безопасность

## 3. Рекомендации по улучшению

### Методы защиты данных:

| Данные     | Шифрование          | Обезличивание   | Доп. меры    |
| ---------- | ------------------- | --------------- | ------------ |
| PII        | AES-256             | Псевдонимизация | RBAC         |
| PHI        | E2E-шифрование      | Токенизация     | Watermarking |
| Финансовые | TLS 1.3+            | Маскирование    | Audit logs   |
| HR         | Database Encryption | Агрегация       | 2FA          |

### Механизм тегирования:

1. Внедрение классификации данных:
   - `public`, `internal`, `confidential`, `restricted`
2. Инструменты:
   - Microsoft Purview
   - Apache Atlas
   - Самописное решение на Python + Elastic

### Инструменты и меры:

1. **Инфраструктура**:

   - Vault для хранения секретов (HashiCorp/1С)
   - SIEM-система (Splunk/Wazuh)
   - DLP (DeviceLock/СёрчИнформ)

2. **Процессы**:

   - Внедрение Privacy by Design
   - Регулярные аудиты безопасности
   - Обязательное обучение сотрудников

3. **Архитектура**:
   - Микросервисы с изолированным доступом
   - API Gateway с валидацией контрактов
   - Отдельный Vault для медицинских данных

## Выводы:

1. Требуется срочная миграция с Excel на защищённое хранилище
2. Необходимо внедрить систему управления доступом (RBAC/ABAC)
3. Критически важно обеспечить шифрование данных в transit/at rest
4. Для соответствия 152-ФЗ требуется назначить ответственного и внедрить DLP
