# Проектирование решения с Privacy by Design для "Медикаменте"

## 1. Дополнительные блоки в архитектуре (C4-уровень)

### 1.1. Новые ключевые компоненты:

| Блок                            | Назначение                                    | Реализация Privacy by Design                                                                      |
| ------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **Identity & Access Gateway**   | Централизованная аутентификация и авторизация | - ABAC-политики<br>- Многофакторная аутентификация<br>- JWT с ограниченным TTL                    |
| **Data Classification Service** | Автоматическое тегирование данных             | - NLP-анализ контента<br>- Интеграция с Microsoft Purview<br>- Водяные знаки для PHI              |
| **Audit & Monitoring Hub**      | Центр аудита безопасности                     | - Логирование всех операций с PII/PHI<br>- Интеграция с SIEM<br>- Алёрты на аномалии              |
| **Privacy-Preserving ETL**      | Безопасная обработка данных                   | - Деидентификация перед анализом<br>- Дифференциальная приватность<br>- Tokenization-as-a-Service |

### 1.2. Модификация существующих блоков:

- **API Gateway** → Добавить:
  - Валидацию контрактов на наличие PII
  - Автоматическую маскировку ответов
  - Rate-limiting для медицинских API
- **База данных** → Внедрить:
  - Column-level encryption для PHI
  - Dynamic Data Masking для DEV-сред
  - Таблицы-аудита для всех CRUD-операций

## 2. Аналитический слой с Privacy by Design

### 2.1. Архитектура аналитического стека:

```
[Источники] → [Privacy Gateway] → [Аналитический Sandbox] → [BI-система]
↑
[Data Clean Room]
```

### 2.2. Ключевые механизмы:

1. **Privacy Gateway**:

   - Автоматическая анонимизация (k-анонимность)
   - Контроль минимально необходимого набора данных
   - Генерация синтетических датасетов для тестирования

2. **Data Clean Room**:

   - Secure Multi-Party Computation для кросс-аналитики
   - Federated Learning для ML-моделей
   - Контроль дифференциальной приватности (ε < 0.5)

3. **Аналитический Sandbox**:
   - Изолированная среда с fake-PHI для разработчиков
   - Airflow с privacy-aware DAGs
   - Автоматическая проверка на re-identification risks

### 2.3. Технологический стек:

| Компонент              | Варианты реализации                        |
| ---------------------- | ------------------------------------------ |
| Анонимизация           | ARX, PySyft, Presidio                      |
| Data Clean Room        | Google Confidential Space, AWS Clean Rooms |
| Мониторинг приватности | OpenDP, IBM Security Guardium              |

## 3. Принципы интеграции в текущие процессы

### 3.1. Жизненный цикл данных:

1. **Сбор**:

   - Оптический распознаватель (не хранит сканы)
   - Веб-формы с client-side маскированием

2. **Хранение**:

   - Шифрование на уровне БД (TDE + Column-level)
   - Геораспределённое хранение (РФ-ЦОДы)

3. **Использование**:
   - Just-in-Time дешифрование
   - Privacy-aware логгирование (маскированные логи)

### 3.2. Контрольные точки:

- **Design Review**: Проверка архитектуры на Privacy Impact Assessment
- **Pre-Prod**: Тестирование на синтетических данных
- **Production**: Continuous Privacy Monitoring

## Выводы:

1. Внедрение Data Clean Room критично для работы с партнёрами
2. Privacy Gateway должен стать обязательным компонентом всех API
3. Для аналитики необходимо 2 параллельных контура - с реальными и синтетическими данными
